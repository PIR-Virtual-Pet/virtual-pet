# PIR
Кейс 8. Виртуальный питомец

## Декомпозиция и реализация методов

В `pet.py` реализован класс `Pet`: он хранит состояние питомца и управляет
его действиями. Общие правила обработки действий вынесены в метод `_apply_action()`.

Каждый объект `Pet` хранит имя, жизнь, счастье, голод, признак существования
`is_alive` и предыдущий штраф `last_damage`. Метод `__init__()` задаёт начальное
состояние: счастье и голод равны 2. Имя должно быть непустой строкой,
жизнь — положительным целым числом (кроме `bool`).

| Метод | Изменение счастья | Изменение голода |
| --- | --- | --- |
| `feed()` — покормить | 0 | −2 |
| `stroke()` — погладить | +1 | +1 |
| `give_treat()` — дать вкусняшку | +2 | −1 |
| `walk()` — погулять | +1 | +3 |
| `ignore()` — игнорировать | −1 | +1 |

Все действия используют общий метод `_apply_action()`. После изменения показателей
он проверяет голод: если тот больше 5, вычитает из жизни штраф. При последовательных
действиях с таким голодом штраф растёт: 1, 2, 3 и далее. При голоде не больше 5
штраф сбрасывается. Это правило действует и после кормления. Голод может быть отрицательным.

Если жизнь или счастье стали не больше нуля, питомец исчезает (`is_alive = False`),
а жизнь ограничивается снизу нулём. Последующие действия вызывают `RuntimeError`.
`get_stats()` возвращает новый словарь со статистикой, не меняя состояние.

## Спецификация REST API

Описание эндпоинтов будущего RESTful-сервера поверх класса `Pet`. Сервер не
содержит игровых правил: он принимает HTTP-запросы, вызывает соответствующие
методы `Pet` и возвращает результат `get_stats()`. Вся логика изменения
показателей остаётся в классе.

### Общие соглашения

- Базовый путь — `/api/v1`. Префикс версии позволяет менять API в дальнейшем,
  не ломая уже написанных клиентов.
- Формат данных — JSON. Запросы с телом отправляются с заголовком
  `Content-Type: application/json`, клиент указывает `Accept: application/json`.
  Ответы сервера отдаются с `Content-Type: application/json`.
- Идентификатор питомца — целочисленный `id`, который сервер присваивает при
  создании. Кличка (`name`) — обычное поле данных: она может повторяться у разных
  питомцев и содержать пробелы, кириллицу и символы вроде `/`, поэтому в пути
  не используется.
- Коллекция питомцев хранится на стороне сервера; класс `Pet` про `id` и про
  других питомцев ничего не знает и не требует изменений.

### Представление питомца

Объект питомца в ответах сервера:

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | `int` | Идентификатор, присвоенный сервером при создании |
| `name` | `string` | Кличка питомца (поле `name` объекта `Pet`) |
| `life` | `int` | Текущая жизнь; не бывает меньше нуля |
| `happiness` | `int` | Текущее счастье |
| `hunger` | `int` | Текущий голод; может быть отрицательным |
| `is_alive` | `bool` | `false`, если питомец исчез |

Поля `life`, `happiness`, `hunger`, `is_alive` и `name` берутся из `get_stats()`
без изменений. Служебное поле `last_damage` наружу не отдаётся: это деталь
реализации правил, а не часть состояния, которое показывают пользователю.

### Сводная таблица эндпоинтов

| Название действия | Локейшн (URL) | Тип запроса | Описание запроса и ответа |
| --- | --- | --- | --- |
| Создать питомца | `/api/v1/pets` | `POST` | Принимает JSON с обязательными `name` (непустая строка) и `life` (целое число больше нуля). Возвращает `201 Created`, заголовок `Location` и объект питомца. При неверных данных — `400 Bad Request` (`VALIDATION_ERROR`). |
| Получить список питомцев | `/api/v1/pets` | `GET` | Не принимает параметров. Возвращает `200 OK` и JSON-массив объектов питомцев; если питомцев нет — пустой массив `[]`. |
| Получить статистику питомца | `/api/v1/pets/{id}` | `GET` | Принимает целочисленный `id` в пути. Возвращает `200 OK` и объект питомца. Если питомца нет — `404 Not Found` (`PET_NOT_FOUND`). |
| Выполнить действие над питомцем | `/api/v1/pets/{id}/actions` | `POST` | Принимает `id` в пути и JSON с полем `action`; допустимы `feed`, `stroke`, `give_treat`, `walk`, `ignore`. | Удалить питомца | `/api/v1/pets/{id}` | `DELETE` | Принимает целочисленный `id` в пути. Возвращает `204 No Content` без тела. Если питомца нет — `404 Not Found` (`PET_NOT_FOUND`). |

### Создание питомца

`POST /api/v1/pets`

Тело запроса:

```json
{
  "name": "Барсик",
  "life": 10
}
```

Оба поля обязательны и повторяют параметры конструктора `Pet(name, life)`.
Начальные счастье и голод задаёт сам класс, в запросе их передавать нельзя.
Пробелы по краям клички обрезаются (`name.strip()` в конструкторе).

Ответ `201 Created`, заголовок `Location: /api/v1/pets/1`:

```json
{
  "id": 1,
  "name": "Барсик",
  "life": 10,
  "happiness": 2,
  "hunger": 2,
  "is_alive": true
}
```

Ошибки:

- `400 Bad Request` (`VALIDATION_ERROR`) — `name` не строка или пустое после
  обрезки пробелов, либо `life` не целое положительное число (в том числе если
  передан `bool`). Соответствует `TypeError` и `ValueError` в `Pet.__init__()`.

Одинаковые клички не считаются ошибкой: питомцы различаются по `id`.

### Получение списка питомцев

`GET /api/v1/pets`

Ответ `200 OK` — массив представлений питомцев. Исчезнувшие питомцы остаются
в списке с `is_alive: false`, пока их не удалят.

```json
[
  {
    "id": 1,
    "name": "Барсик",
    "life": 8,
    "happiness": 3,
    "hunger": 1,
    "is_alive": true
  },
  {
    "id": 2,
    "name": "Рекс",
    "life": 10,
    "happiness": 2,
    "hunger": 2,
    "is_alive": true
  }
]
```

Если питомцев нет, возвращается пустой массив `[]` и тот же код `200 OK`.

### Получение статистики питомца

`GET /api/v1/pets/{id}`

Ответ `200 OK`:

```json
{
  "id": 1,
  "name": "Барсик",
  "life": 8,
  "happiness": 3,
  "hunger": 1,
  "is_alive": true
}
```

Эндпоинт работает и для исчезнувшего питомца: объект `Pet` остаётся доступен
для просмотра финальной статистики, поэтому сервер отдаёт её с `is_alive: false`.

Ошибки:

- `404 Not Found` (`PET_NOT_FOUND`) — питомца с таким `id` нет.

### Действие над питомцем

`POST /api/v1/pets/{id}/actions`

Все пять действий выполняются через один эндпоинт: вид действия передаётся
в теле запроса. Это избавляет от пяти почти одинаковых маршрутов и позволяет
добавлять новые действия, не меняя набор путей.

Тело запроса:

```json
{
  "action": "walk"
}
```

Допустимые значения `action` и вызываемые методы `Pet`:

| `action` | Метод `Pet` | Счастье | Голод |
| --- | --- | --- | --- |
| `feed` | `feed()` | 0 | −2 |
| `stroke` | `stroke()` | +1 | +1 |
| `give_treat` | `give_treat()` | +2 | −1 |
| `walk` | `walk()` | +1 | +3 |
| `ignore` | `ignore()` | −1 | +1 |

Значения совпадают с именами методов класса, поэтому сопоставление однозначно
и не требует отдельной таблицы переименований на стороне сервера.

Ответ `200 OK` — состояние питомца после действия и поле `action` с выполненным
действием. Для питомца из примера выше (`life: 8`, `happiness: 3`, `hunger: 1`):

```json
{
  "id": 1,
  "name": "Барсик",
  "life": 8,
  "happiness": 4,
  "hunger": 4,
  "is_alive": true,
  "action": "walk"
}
```

Штраф за голод, обнуление серии штрафов и исчезновение питомца рассчитываются
внутри `_apply_action()` до формирования ответа, поэтому в ответе всегда
возвращается итоговое состояние. Если действие привело к исчезновению, сервер
возвращает `200 OK` с `is_alive: false` — действие было выполнено успешно,
таков его результат.

Ошибки:

- `400 Bad Request` (`UNKNOWN_ACTION`) — поле `action` отсутствует или содержит
  значение не из таблицы выше.
- `404 Not Found` (`PET_NOT_FOUND`) — питомца с таким `id` нет.
- `409 Conflict` (`PET_IS_GONE`) — питомец уже исчез (`is_alive: false`) и не
  может действовать. Соответствует `RuntimeError` в `Pet._apply_action()`.

### Удаление питомца

`DELETE /api/v1/pets/{id}`

Удаляет питомца из коллекции сервера. Применимо и к живому, и к исчезнувшему
питомцу.

Ответ `204 No Content`, без тела: возвращать удалённый объект незачем.

Ошибки:

- `404 Not Found` (`PET_NOT_FOUND`) — питомца с таким `id` нет.

### Формат ошибок

Все ошибки возвращаются в одном виде: машиночитаемый `code` для клиента и
`message` для отладки и вывода пользователю.

```json
{
  "error": {
    "code": "PET_IS_GONE",
    "message": "Питомец Барсик исчез и больше не может действовать."
  }
}
```

| `code` | HTTP | Когда возникает |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | Некорректные `name` или `life` при создании |
| `UNKNOWN_ACTION` | 400 | Неизвестное или отсутствующее значение `action` |
| `PET_NOT_FOUND` | 404 | Питомца с указанным `id` нет |
| `PET_IS_GONE` | 409 | Действие над исчезнувшим питомцем |
